第4课：自动求导机制（Autograd）——从原理到实现的深度剖析

4.1 为什么需要梯度？——机器学习的最优化本质

4.1.1 机器学习的核心问题

机器学习，尤其是深度学习，本质上是一个最优化问题。我们有一个模型（比如一个神经网络），它有很多可调节的参数（权重和偏置）。模型接收输入数据，产生输出预测。

模型当前的预测结果与真实结果之间存在差距，这个差距用损失函数（Loss Function）来衡量。损失函数的值越大，表示模型表现越差。

我们的目标就是：找到一组参数值，使得损失函数的值最小。

这就像你在一个陌生的山谷中，大雾弥漫，你看不到谷底在哪里，但你脚踩的地方能感觉到坡度。你要找到山谷的最低点。

4.1.2 梯度：指向"山坡"的方向

梯度就是那个"坡度"。它是一个向量，指向函数值增长最快的方向。

如果你的位置在山的半山腰，梯度指向的是上坡方向。我们要下山，就要沿着梯度的反方向迈出一步。这就是梯度下降法（Gradient Descent）的核心思想。

参数更新的基本公式是：

\[ \text{新参数} = \text{旧参数} - \text{学习率} \times \text{梯度} \]

  • 学习率（Learning Rate）：决定每一步迈多大。步子太小，下山太慢；步子太大，可能错过谷底甚至滚下山。

【名词解释】最优化（Optimization）：在数学上，最优化是寻找使某个目标函数（在此为损失函数）达到最大值或最小值的一组输入变量（在此为模型参数）的过程。

【名词解释】梯度下降（Gradient Descent）：一种迭代优化算法，通过计算目标函数在当前点的梯度，并沿着梯度反方向更新变量，以寻找局部最小值。它是最基础的神经网络训练算法。

4.2 为什么需要反向传播？——梯度的计算效率问题

4.2.1 数值微分法（最笨的方法）

假设你的网络有1亿个参数，你想知道每个参数的微小变化会如何影响最终的损失。一种最朴素的方法是数值微分：

对于每个参数 \(w_i\)，你给它加上一个微小的扰动 \(\varepsilon\)（比如 0.0001），计算一个新的损失 \(L(w_i + \varepsilon)\)，然后计算 \((L(w_i + \varepsilon) - L(w_i)) / \varepsilon\) 来估计梯度。

# 伪代码展示数值微分的低效性
def compute_gradient_numerically(model, loss_fn, data, epsilon=1e-5):
    gradients = []
    for each_parameter in model.all_parameters():
        # 1. 保存原始值
        original_value = each_parameter.value

        # 2. 加微小扰动，计算新损失
        each_parameter.value += epsilon
        loss_plus = loss_fn(model(data))

        # 3. 恢复原值
        each_parameter.value = original_value

        # 4. 计算梯度估计
        grad = (loss_plus - loss_original) / epsilon
        gradients.append(grad)
    return gradients

4.2.2 数值微分的致命缺陷

用这种方法计算所有参数的梯度，需要1次前向传播（计算原始损失）+ N次前向传播（N为参数个数）。对于1亿个参数，你需要进行1亿零1次前向传播。即使每次前向传播只需要1毫秒，总共也需要大约11.5天。这还是一次迭代的时间！显然不可行。

4.2.3 反向传播：一次前向，一次反向搞定所有梯度

反向传播（Backpropagation） 是解决这个效率问题的关键。它只需要一次前向传播和一次反向传播，就能同时计算出所有参数的梯度。

核心思想：反向传播利用了微积分中的链式法则（Chain Rule）。它先计算出输出端（损失）对每个中间变量的梯度，然后从后往前，将这些梯度"传递"回输入端，复用已经计算好的结果，避免了重复计算。

想象一下流水线：前向传播是从原料（输入）到成品（损失）的过程。反向传播则是从成品出发，逆向追溯每个环节对最终成本的"贡献度"。

【名词解释】链式法则（Chain Rule）：微积分中的一个基本法则，用于计算复合函数的导数。如果 \(y = f(g(x))\)，那么 \(dy/dx = (dy/dg) \cdot (dg/dx)\)。反向传播正是通过反复应用链式法则，从输出端反向逐层计算梯度。

【名词解释】前向传播（Forward Propagation）：数据从输入层进入，逐层计算并通过网络，最终得到输出（或损失）的过程。它是反向传播的"信息记录"阶段。

4.3 计算图：自动求导的"工程蓝图"

4.3.1 为什么PyTorch需要记录"操作历史"？

要进行反向传播，PyTorch必须知道：

  1. 从输入到输出，经过了哪些操作（加、乘、卷积等）。
  2. 这些操作发生的顺序。
  3. 每个操作涉及了哪些张量。

这个"历史记录"就是计算图（Computation Graph）。

4.3.2 计算图的构建：每个张量都是一个"历史档案"

当你执行 x = torch.tensor(2.0, requires_grad=True) 时，你创建了一个特殊的张量，它自带一个"空档案"（grad_fn=None），表示它本身不是一个运算的结果。

当你执行 y = x * x 时，PyTorch在幕后做了三件事：

  1. 执行计算：计算 x*x 的值。
  2. 创建新张量 y。
  3. 在 y 的"档案"（grad_fn）里，记录了它的"出生信息"：它是一个乘法操作（MulBackward）的产物，这个操作的输入是 x。

当你执行 z = y.sum() 时，PyTorch又创建了 z，并在 z.grad_fn 中记录了它是一个求和操作（SumBackward）的产物。

【名词解释】有向无环图（DAG, Directed Acyclic Graph）：计算图在计算机科学中是一种有向无环图，其中节点代表张量或运算，边代表数据流向。它保证了信息可以沿着边从输入流向输出（前向），也可以从输出追溯回输入（反向），且不会形成死循环。

4.3.3 深入 grad_fn：里面到底存了什么？

grad_fn 不仅仅是一个标签。它是一个函数对象，包含了如何计算这个操作的反向传播梯度的方法（backward()）。以 y = x * x 的 grad_fn（MulBackward）为例，它知道：

  • 这个操作是乘法。
  • 它的输入是 x。
  • 当反向传播时，梯度需要乘以另一个输入（因为 \(\frac{d(x^2)}{dx} = 2x\)）。
import torch

x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = x * x
z = y.sum()

print("节点 x 的 grad_fn:", x.grad_fn)
print("节点 y 的 grad_fn:", y.grad_fn)
print("节点 z 的 grad_fn:", z.grad_fn)
节点 x 的 grad_fn: None
节点 y 的 grad_fn: <MulBackward0 object at 0x000000003661C310>
节点 z 的 grad_fn: <SumBackward0 object at 0x000000003665A260>

这个 grad_fn 就是反向传播的 "活地图"。它把整个前向计算过程串联成了一个可追溯的链条。

4.4 backward() 的内部机制：逆向遍历并计算

当你调用 z.backward() 时，PyTorch 会在后台执行一个精密的流程：

  1. 定位起点：PyTorch 从调用 backward() 的根节点 z 开始。它查看 z.grad_fn，发现它是一个 SumBackward。
  2. 逆向遍历：SumBackward 知道它的前向输入是 y。它会根据求和操作的反向传播规则，计算出对 y 的梯度，并将这个梯度传递给 y。
  3. 递归传递：y 收到梯度后，它的 grad_fn（MulBackward）知道它的输入是 x。它使用乘法操作的反向传播规则（乘以另一个输入），计算出对 x 的梯度。
  4. 到达叶子节点并累加：最终，梯度到达了叶子节点 x。PyTorch 将计算出的梯度累加到 x.grad 属性中。

这个"逆向遍历"的过程在C++底层高度优化并并行执行，比我们手动实现要快几个数量级。

4.5 为什么梯度是累加的？——设计哲学与工程考量

这是PyTorch设计中一个非常核心，也容易让人困惑的决定。

4.5.1 为什么不直接覆盖？

如果每次 backward() 都直接覆盖 grad，那么每次反向传播都是孤立的，这虽然简单，却极大地限制了灵活性。

4.5.2 梯度累加带来的灵活性

场景一：复杂的损失函数

很多模型的损失函数不是单一的，而是由多个部分加权求和组成的，例如 loss = loss_1 + loss_2。我们希望在同一组参数上，同时计算 loss_1 和 loss_2 的梯度，并将它们结合起来。

loss1 = ...
loss2 = ...
loss = loss1 + loss2
loss.backward()  # 一次反向传播，梯度的累加自动完成

你只需要进行一次反向传播，对 loss 求导，由于线性关系，其结果就自动等于 loss1 和 loss2 梯度的和。

场景二：梯度累积（Gradient Accumulation）

这是深度学习中的一个重要技巧。当你的GPU显存不够，无法放入大的 batch_size 时，你可以模拟大的 batch_size。具体做法是：将一个大批次分成几个小批次，逐个计算每个小批次的损失并调用 backward()。因为梯度是累加的，所以最后 x.grad 中存储的就是所有小批次梯度的总和。然后，你再调用 optimizer.step() 更新一次参数。这就相当于用一个大的 batch_size 进行了一次梯度计算和更新。

4.5.3 如果不累加会怎么样？

如果梯度是覆盖的，那么上述所有场景都将失效。你将无法组合多个损失，也无法实现梯度累积。PyTorch 将 backward() 的职责定义为"计算并贡献（累加）梯度"，而把"清零"的职责交给了用户，这在设计上更灵活，责任更清晰。

4.6 停止求导的必要性：detach() 与 torch.no_grad()

4.6.1 为什么需要停止求导？

  1. 推理/评估阶段：在模型训练完成后，或者在一个验证集上评估模型性能时，我们只想得到模型的输出，而不需要（也不应该）更新任何参数。构建计算图会消耗额外的时间和内存，完全没有必要。
  2. 转移/提取特征：有时候，我们希望将某些张量从计算图中"抽离"出来，作为一个独立的数值，用于后续的、不需要梯度的处理。

4.6.2 torch.no_grad()：高效的上下文管理器

这是一个上下文管理器，它临时性地将 requires_grad 设置为 False，并阻止整个计算图的构建。这是最推荐的方式，因为它最高效。

x = torch.tensor([1.0, 2.0], requires_grad=True)
y = x * 2  # 这里计算图被构建了，y.requires_grad 为 True

with torch.no_grad():
    # 在这个块内，所有操作都不会被记录
    z = x * 3  # 这里不会构建计算图，z.requires_grad 为 False
    w = y + 1  # 注意：y 虽然需要梯度，但在块内操作 y，不会影响 y 本身
               # w 的 requires_grad 也为 False
print("w.requires_grad:", w.requires_grad)
w.requires_grad: False

4.6.3 .detach()：精准的"切割手术"

.detach() 是一个张量方法。它会切断该张量与当前计算图之间的关联，返回一个新的张量，这个新张量与原始张量共享数据，但 requires_grad 为 False。

理解 .detach() 的关键：它是"源头"上的切断，而非"路径"上的阻断。

你可以这样理解：

  • 原始 x 的计算图不受影响。
  • y_detached 是一个全新的起点，它从 y 那里"复制"了数值，但撕毁了与 y 的"血缘关系"证明。
  • 所有对 y_detached 进行的后续操作，都会围绕这个新起点构建一个全新的、独立的计算图。这个新图与原始的 x、y 没有任何关联。
x = torch.tensor([1.0, 2.0], requires_grad=True)
y = x * 2                     # y 在原始计算图中
y_detached = y.detach()       # y_detached 从原始图中剥离出来，成为一个新起点

# 对剥离出来的 y_detached 进行后续操作
z = y_detached * 3
w = z + 1

# 检查张量的属性
print("原始计算图节点 y.requires_grad:", y.requires_grad)
print("原始计算图节点 y.grad_fn:", y.grad_fn)

print("\n剥离后的新起点 y_detached.requires_grad:", y_detached.requires_grad)
print("剥离后的新起点 y_detached.grad_fn:", y_detached.grad_fn)

print("\n基于新起点的 z.requires_grad:", z.requires_grad)
print("基于新起点的 z.grad_fn:", z.grad_fn)
print("基于新起点的 w.requires_grad:", w.requires_grad)
print("基于新起点的 w.grad_fn:", w.grad_fn)   
原始计算图节点 y.requires_grad: True
原始计算图节点 y.grad_fn: <MulBackward0 object at 0x000000003F083490>

剥离后的新起点 y_detached.requires_grad: False
剥离后的新起点 y_detached.grad_fn: None

基于新起点的 z.requires_grad: False
基于新起点的 z.grad_fn: None
基于新起点的 w.requires_grad: False
基于新起点的 w.grad_fn: None

核心结论：

  • y_detached.requires_grad 为 False，因为它从 y 剥离时，带走了数据，但舍弃了"需要梯度"这个属性。
  • 由于 y_detached 是 False，那么它参与的所有后续运算（z、w）的 requires_grad 也都是 False，因此它们的 grad_fn 都是 None。它们不在任何计算图中，只是一个普通的数值载体。
  • .detach() 是创建一个独立的"数值副本"，这个副本不再属于原始计算图，因此它的 requires_grad 为 False，grad_fn 为 None。

错误理解 vs 正确理解：

错误理解 正确理解
.detach() 只是切断了反向传播的路径，但后续操作仍可能被记录。 .detach() 创建了一个全新的、不依赖任何计算图的根节点。从此节点开始的所有运算，都不会被记录到任何计算图中。
后续操作的 grad_fn 可能存在，只是与原始图无关。 后续操作的 requires_grad 都为 False，因此 grad_fn 一定为 None。它们根本不属于任何计算图。

.detach() 的典型使用场景：

  • 提取特征用于分析：你想把网络中间层的输出拿出来，做一些与训练无关的处理（如可视化、保存为特征文件），这时可以用 .detach() 避免这些操作干扰网络训练。
  • 对抗样本生成：在一些攻击算法中，你可能需要先冻结模型，然后对输入进行修改，这时可以用 .detach() 切断模型参数与输入修改之间的梯度关系。
  • 强化学习中的经验回放：当你从经验池中采样数据进行训练时，这些数据是历史产生的，不应该影响当前策略网络的梯度计算。
# 实际应用示例：提取特征用于可视化
model = ...  # 假设有一个训练好的模型
x = torch.randn(1, 3, 224, 224, requires_grad=False)  # 输入图片

with torch.no_grad():  # 推理时推荐使用 no_grad，而非 detach
    feature = model.layer3(x)  # 提取某层特征

# 假设你有一个可视化函数，它可能包含需要梯度的操作（例如对比度增强）
# 但你不想让这些操作影响模型本身的参数
feature_for_viz = feature.detach()  # 切离，成为一个独立的数值
visualized = visualize(feature_for_viz)  # 此时 visualized 与模型完全无关

4.6.4 如果不停止求导会怎样？

如果在评估一个大型模型时，没有使用 torch.no_grad()，那么即使你不需要梯度，PyTorch 仍然会耗费大量内存去构建计算图，并浪费计算资源来追踪它。这会导致评估速度变慢，甚至因内存溢出（OOM）而崩溃。

4.7 retain_graph：保留计算图

4.7.1 为什么默认会被释放？

为了最大化内存利用效率，PyTorch 在执行完一次 backward() 后，会默认释放（或说是标记为可回收）计算图。因为绝大多数情况下，你只需要进行一次反向传播来更新参数。

4.7.2 什么时候需要保留？

你需要对同一个计算图进行多次反向传播时。例如：

  • 你有一个大模型，你想先对一部分层更新，再对另一部分层更新。
  • 你在进行一些研究，需要计算二阶导数（即梯度再求导）。

4.7.3 如果忘记释放会怎样？

如果你设置 retain_graph=True 但却没有在之后手动释放（del），该计算图会一直驻留在内存中，直到变量被销毁。在一个训练循环中，这会导致每轮迭代都保留一个计算图，最终导致内存泄漏（Memory Leak），程序会逐渐耗尽所有显存。

x = torch.tensor([1.0, 2.0], requires_grad=True)
y = x * x

# 第一次反向传播，并告诉 PyTorch "别急着删"
y.sum().backward(retain_graph=True)
print("第一次 x.grad:", x.grad)

# 第二次反向传播，仍然可以使用同一个计算图
y.prod().backward()  # prod() 对所有元素求乘积
print("第二次 x.grad:", x.grad)
第一次 x.grad: tensor([2., 4.])
第二次 x.grad: tensor([10.,  8.])

4.8 源代码级思考：backward() 到底做了什么？

虽然我们无法完全剖析PyTorch庞大的C++源码，但可以理解其核心概念：

  1. 查找根节点：从调用 .backward() 的 loss 张量开始，其 grad_fn 指向了最后一个操作（例如 LossBackward）。
  2. 触发反向传播回调：调用 grad_fn 的 apply() 方法。每个 grad_fn 内部都实现了 apply()，它知道如何计算该操作对输入的梯度。
  3. 反向传递数据：apply() 方法会计算出梯度（一个或多个张量），并将它们传递给前一个节点（即该操作的输入节点）的 grad_fn。
  4. 累加结果：当梯度最终到达一个叶子张量（grad_fn 为 None）时，PyTorch 将其累加到该张量的 grad 属性上。

这个过程是深度优先遍历（DFS）的，确保所有依赖都被满足。

# 练习4：区分 torch.no_grad() 和 .detach()

4.11 总结

知识点 核心理解
梯度下降 沿梯度反方向更新参数以最小化损失函数
反向传播 利用链式法则从损失出发逆向计算所有参数的梯度
计算图 记录前向操作历史的有向无环图，是反向传播的基础
grad_fn 每个非叶子张量携带的反向传播函数对象
梯度累加 多次 backward() 的梯度会相加，支持多损失组合和梯度累积
torch.no_grad() 上下文管理器，临时禁用梯度追踪，推理时必用
.detach() 从计算图中切断张量，返回共享数据但不需梯度的新张量
retain_graph 保留计算图以支持多次反向传播，需注意内存泄漏风险
叶子张量 由用户直接创建的张量，grad_fn=None，.grad 会保留梯度
.retain_grad() 让非叶子张量也保留梯度，用于调试或特殊需求
